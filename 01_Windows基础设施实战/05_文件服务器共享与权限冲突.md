1. 掌握 Windows Server 文件共享服务的部署与权限配置。
2. 深入理解 NTFS 权限与共享权限的区别及“取交集”原则。
3. 掌握域环境下的文件服务器访问排障流程。

# 四、 故障注入与排障实战

## 故障场景 A：共享权限与 NTFS 权限的冲突
- **制造故障**：在 Server 上，右键 `CompanyShare` -> 属性 -> 安全 -> 高级 -> 禁用继承 -> 将继承的权限转换为此对象的显式权限。然后把 `zhangsan` 用户直接添加进去，赋予“完全控制”。但是去“共享”选项卡，把共享权限里的 `Authenticated Users` 改成仅“读取”。
- **现象**：在 Win11 上，`zhangsan` 尝试修改或删除文件，提示“需要来自 ... 的权限才能对此文件夹进行更改”或“拒绝访问”。
- **排查过程**：
  1. 确认用户已登录域，网络通信正常。
  2. 检查共享权限，发现是只读；检查 NTFS 权限，发现是完全控制。
  3. 定位到 Windows 的权限交集原则。
- **根因**：当共享权限和 NTFS 权限冲突时，最终生效的是两者中最严格的权限（取交集）。共享权限为“读取”，NTFS 为“完全控制”，最终用户得到的是“读取”。
- **修复**：将共享权限也改为“更改”或“完全控制”，客户端无需重启，刷新后即可修改。
- **面试话术提炼**：用户反馈明明给了完全控制却无法修改文件，首先要确认是共享权限还是 NTFS 权限配置的，共享权限和 NTFS 权限取最严格的交集。

## 故障场景 B：IP 能访问，域名无法访问
- **制造故障**：在 Server 的 DNS 管理器中，把 `fileserver.lab.local` 的 A 记录改成不可达的 IP（如 `192.168.10.250`）。
- **现象**：在 Win11 上，输入 `\\192.168.10.10\CompanyShare` 可以正常访问；输入 `\\fileserver.lab.local\CompanyShare` 提示“找不到网络路径”或错误代码 `0x80070035`。
- **排查过程**：
  1. 输入 IP 能通，说明底层网络、SMB 服务和权限都没问题。
  2. 输入域名不通，怀疑是名称解析问题。
  3. 在 Win11 执行 `ping fileserver.lab.local`，发现解析到了 `192.168.10.250`。
  4. 执行 `ipconfig /displaydns` 确认是否有缓存残留，使用 `ipconfig /flushdns` 清空。
  5. 再次 `ping` 发现仍指向错误 IP，确认是 DNS 服务器记录被篡改。
- **根因**：DNS 记录错误导致域名无法解析到正确的文件服务器 IP。
- **修复**：在 Server 恢复 DNS A 记录，Win11 刷新 DNS 缓存，访问恢复正常。
- **面试话术提炼**：共享访问报错时，先用 IP 测。IP 能通域名不通，一定是 DNS 问题或本地 Hosts 文件问题。逐层剥离网络、服务与解析问题。
## 排障场景 A：无法删除Users用户组
**现象**：无法删除从父系继承的权限，提示需关闭继承。  
**根因**：Windows的NTFS权限默认有继承性，子文件夹会继承父文件夹权限。  
**解决**：在“高级安全设置”中点击“禁用继承”，**选择“转换”**（保留现有权限并转为显式），之后再删除不需要的权限条目。  
	![[Pasted image 20261115150908.png]]
**经验**：修改权限前，先确认其继承状态，避免直接删除父级权限导致意外。

# 五、 知识点提炼：共享权限与 NTFS 权限的区别

| 维度 | 共享权限 (Share Permissions) | NTFS 权限 (Security Permissions) |
| :--- | :--- | :--- |
| **作用层级** | 仅作用于网络访问（SMB 协议） | 作用于本地和网络访问（无论从哪里访问） |
| **生效逻辑** | 与 NTFS 权限取交集（最严格者生效） | 与共享权限取交集（最严格者生效） |
| **适用场景** | 粗粒度控制（读、改、完全控制） | 细粒度控制（可细分到创建文件、读取属性、删除子文件夹等） |
| **本质区别** | 拦截门外的人（网络层面的门卫） | 拦截门内的人（本地系统层面的安保） |

> **面试标准回答**：共享权限只管网络，NTFS 权限既管本地也管网络；两者同时存在时，取交集（谁严格听谁的）。实际工作中一般建议将共享权限设为 Everyone 完全控制，所有权限控制精细度全部交给 NTFS 权限来完成。
