# 一、 实验目的
1. 掌握将 Windows 客户端加入 AD 域的正确流程及前置条件（DNS、时间同步）。
2. 掌握组织单位（OU）、用户与安全组的区别及创建方法。
3. 掌握组策略（GPO）的创建、链接与强制刷新方法。
4. 掌握使用 `gpresult` 工具排查组策略不生效的故障。

# 二、 正常流程：加域与 GPO 下发

## 1. 前置检查（加域失败的三大元凶）
在 Win11 客户端上执行：
- **网络连通性**：`ping 192.168.10.10` 能够通。
- **DNS 指向**：首选 DNS 必须指向 Server 的 IP（`192.168.10.10`）。
- **时间同步**：检查 Win11 与 Server 的时间差不超过 5 分钟（Kerberos 认证要求）。

## 2. Win11 客户端加域
1. 右键“此电脑” → 属性 → 高级系统设置 → 计算机名 → 更改。
	![](<../images/Pasted image 20261102142122.png>)
	![](<../images/Pasted image 20261102142149.png>)
	![](<../images/Pasted image 20261102142155.png>)
2. 选择“域”，输入 `lab.local`。
	![](<../images/Pasted image 20261102142211.png>)
3. 输入域管理员凭据（如 `LAB\Administrator`），提示欢迎加入，重启客户端。
	![](<../images/Pasted image 20261102142218.png>)
	![](<../images/Pasted image 20261102142224.png>)
## 3. 创建组织架构与用户
1. 在 Server 打开“Active Directory 用户和计算机”。
	![](<../images/Pasted image 20261102142241.png>)
2. 右键 `lab.local` → 新建 → 组织单位（OU），命名为 **“测试部”**。 
	![](<../images/Pasted image 20261102142252.png>)
	![](<../images/Pasted image 20261102142415.png>)
3. 在“测试部”里新建用户，例如 `张三`（登录名 `zhangsan`）。
	![](<../images/Pasted image 20261102142427.png>)
	![](<../images/Pasted image 20261102142451.png>)
	![](<../images/Pasted image 20261102142503.png>)

## 4. 下发组策略（GPO）
1. 打开“组策略管理”工具。
	![](<../images/Pasted image 20261102142516.png>)
2. 右键“测试部” OU → **在这个域中创建 GPO 并在此处链接**，命名为 **“隐藏C盘策略”**。
	![](<../images/Pasted image 20261102142525.png>)
	![](<../images/Pasted image 20261102142608.png>)
3. 右键该 GPO → 编辑。
	![](<../images/Pasted image 20261102142651.png>)
4. 依次展开：**用户配置** → **策略** → **管理模板** → **Windows 组件** → **文件资源管理器**。
	![](<../images/Pasted image 20261102142809.png>)
5. 双击 **“隐藏‘我的电脑’中的这些指定的驱动器”**，选择“已启用”，并在下拉框中选择“**仅限制 C 驱动器**”。
	![](<../images/Pasted image 20261102142857.png>)
	![](<../images/Pasted image 20261102142936.png>)
6. 点击确定保存。

## 5. 验证策略是否生效
1. 在 Win11 上，注销当前管理员账户，使用刚创建的域用户 `LAB\zhangsan` 登录。
	![](<../images/Pasted image 20261102143027.png>)
	![](<../images/Pasted image 20261102143032.png>)
2. 打开 CMD，执行 `gpupdate /force` 强制刷新策略。
	![](<../images/Pasted image 20261102143319.png>)
3. 打开“此电脑”，验证 C 盘是否已被隐藏。
	![](<../images/Pasted image 20261102143331.png>)

# 三、 故障注入与排障实战

## 故障场景 A：加域失败（模拟 DNS 指向错误）
- **制造故障**：在 Win11 上，将首选 DNS 改为外网 DNS（如 `8.8.8.8`），再次尝试加域。
	- ![](<../images/Pasted image 20261102144607.png>)
- **现象**：提示“**找不到网络路径**”或“**无法联系域控**”。
	- ![](<../images/Pasted image 20261102144839.png>)
- **排查过程**：
  1. `ping lab.local` 解析失败。
	  ![](<../images/Pasted image 20261102144920.png>)
  2. 定位到本地 DNS 指向错误，导致无法解析域控的 SRV 记录。
- **修复**：将 DNS 改回 `192.168.10.10`，加域成功。
	![](<../images/Pasted image 20261102145038.png>)
## 故障场景 B：组策略未生效（模拟用户不在 OU 里）
- **制造故障**：在 AD 中，将 `zhangsan` 从“测试部”OU 移动到默认的 `Users` 容器中。
	- ![](<../images/Pasted image 20261102153856.png>)
	- ![](<../images/Pasted image 20261102153940.png>)
- **现象**：在 Win11 上执行 `gpupdate /force`，C 盘依然可见（策略未生效）。
	- ![](<../images/Pasted image 20261102154111.png>)
- **排查过程**：
  1. 执行 `gpresult /R`。
  2. 在报告中观察“已应用的组策略对象”列表，发现“隐藏C盘策略”没有应用。
  3. 检查“用户详细信息”，发现用户已不在“测试部”OU 中（GPO 链接在 OU 上，失去作用目标）。
- **修复**：将用户移回“测试部”OU，`gpupdate /force` 后恢复生效。

# 四、 附加排障案例：屏幕保护策略未生效（系统未激活的坑）

> **背景说明**：最初下发的是“屏幕保护程序”策略，但客户端未生效，由此引发了以下排障记录。

- **现象**：GPO 显示策略已启用，但 Win11 客户端静置 60 秒后并未启动屏幕保护。
- **排查过程**：
  1. 检查策略配置，确认“启用屏幕保护程序”和“屏幕保护程序超时”均已设置。
  2. 执行 `gpresult /R`，确认策略已成功下发到客户端。
  3. 检查系统激活状态，发现当前 Win11 实验虚拟机处于**未激活**状态。
- **根因分析**：微软从 Windows 10 开始，对未激活的 Windows 系统实施了功能限制。“屏幕保护程序”属于“个性化”模块，在系统未激活状态下，底层授权机制（Licensing）会直接拦截该功能的生效，即使注册表和组策略已正确配置。
- **验证与解决**：
  1. 为了验证 GPO 链路本身没问题，将策略改为“隐藏 C 盘”，客户端 `gpupdate` 后立刻生效，证明域控通信正常。
  2. 最终决定在实验环境中取消屏保策略，改用“隐藏 C 盘”作为组策略实验的标准配置。
- **面试话术提炼**：“遇到组策略配置正确且 `gpresult` 显示应用，但功能不生效时，要考虑系统层面的限制。比如 Windows 未激活会导致个性化策略被底层拦截。先通过下发隐藏驱动器等底层策略验证 GPO 链路，再定位系统环境问题。”

# 五、 知识点提炼：OU 与 组的区别（面试高频）

| 维度 | 组织单位（OU） | 组（Group） |
| :--- | :--- | :--- |
| **本质** | 容器/文件夹（装用户和计算机） | 安全主体（发通行证的集合） |
| **主要用途** | **下发组策略（GPO）**、委派管理权限 | **分配权限**（如文件夹访问、打印机使用） |
| **包含关系** | 可包含用户、计算机、组、子OU | 只能包含用户、计算机、其他组（**不能包含OU**） |
| **面试话术** | “OU 是组织架构，用于下发策略和管理。” | “组是权限分配，用于控制资源访问。” |
